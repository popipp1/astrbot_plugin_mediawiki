# AstrBot MediaWiki 页面查询与变更推送插件

通过 MediaWiki Action API 查询页面摘要与链接。实现参考了 SILI-agent 的 MediaWiki 插件，但使用 AstrBot 当前的 Star 插件接口和异步 HTTP 客户端。

当前版本：`1.7.0`。正文优先的紧凑预览，新增移动日志和历史修订重定向状态推送；新安装默认每条最多 700 字符。

### 1.7.0 正文优先与页面事件

- 有正文改动时，空行调整汇总为末尾提示，不占正文名额。连续单侧新增/删除的章节标题、可选年份与第一条内容合为一项；独立标题降为较低优先级，不跨未修改行或两侧强行组合。
- 精确验证完整旧/新行后，纯插入和删除使用局部摘要，附近文字中的 `▸` 指示操作位置。短内链文字补充附近词语；连续同一行的数字替换共用行号提示。源码截取优先避开未闭合模板、内链，无法完整保留时标注“源码截断”。这不是模板展开或专用参数语义解析。
- `change_include_moves=true`：从 RecentChanges 的日志事件读取 `move`/`move_redir`，输出旧标题、新标题、操作者、时间、摘要、是否保留重定向及日志链接，不显示虚假的字节增减。隐藏或缺少目标标题的日志略过。单条目按 pageid 继续追踪并立即更新标题；分类订阅使用现有成员快照、前后标题匹配，不承诺还原任意历史分类成员关系。
- `change_detect_redirects=true`：对命中订阅的编辑和新建，按**对应修订 ID**读取主槽内容，使用站点公布的重定向指令别名识别新建重定向、改为重定向、目标变更及取消重定向。保留目标章节。新建仍用条目链接，既有页面状态变更用差异链接，并保留其他正文改动。
- 重定向识别每批最多读取 20 个修订的全文，首次还读取站点指令别名；不使用当前页面重定向标记解释历史事件。缺失/隐藏源码、非 Wikitext、前置注释或无法确认的语法保守回退为普通通知。不计算模板展开、最终跳转链或软重定向。源码不写入监控状态。
- 文本预览设为 0 **不会关闭**重定向识别；如需停止额外历史全文请求，同时将 `change_detect_redirects=false`。两个新开关均默认开启，保存过的长度、预览数量等配置不被覆盖。
- 移动和普通编辑共用持久化 RCID 去重及失败队列。若 API 同时给出移动所生成的新重定向，仅在**同时间、同操作者、同源标题、目标一致、不同且有效 pageid、明确保留重定向**时，按接收会话合并提醒。移动记录先出现或同批出现时可跨轮询/重启去重；若新建通知已经先行发出，再收到迟到移动日志，仍发送移动通知，不隐藏新增信息。无可靠关联时保留通知。

状态格式升级为 v4，兼容读取 v1–v3；已排队的通知仍使用原文本。暂缓的 Photrans2/ruby 注音及 llcoloredlink 参数专用识别仍未加入，删除、恢复和其他日志事件也不在本版范围内。

```text
血之代偿
移动 | Purrely | 19:27
https://zh.moegirl.org.cn/index.php?title=Special%3ALog&logid=2557593
📦移动至｢血的代价｣
保留旧标题重定向
```

以上移动示例来自实际日志，未执行移动操作。实现依据 [RecentChanges API](https://www.mediawiki.org/wiki/API:RecentChanges) 的日志字段及 [Revisions API](https://www.mediawiki.org/wiki/API:Revisions) 的历史主槽内容；回归测试见 `tests/test_event_push.py`。

### 1.6.0 紧凑差异与结构边界

- 连续单侧新增/删除的表格分隔符和数据行合为一个项目。预览数量为 1 时不会只显示 `|-`。简单单行表格以 `｜` 分隔顶层单元格，空值标注“（空）”；模板与内链参数保持原样。
- 多行或带属性的表格保留整体源码预览。不推断列名、期数等业务含义，不展开日期模板，也不纠正源码中的年份。无法确定结构时回退原文。
- 相同操作按截断前的完整内容计数，例如 `✏添加换行标签（3处）`。只统计实际修改，不统计原有标签；已知不同章节不合并。保留内部行号与位置，短数字或单字替换在有行号时标注位置。未知章节不作定位断言。
- 按旧、新修订 ID 分批获取主槽内容模型（每批最多 50 个修订，不获取全文）。只有两侧都确认为 Wikitext 时启用结构摘要；CSS、JavaScript、模型切换或模型查询失败使用源码预览，不据此推断分类归属或链接效果。模型查询失败不会阻止差异获取与通知。
- 可见差异上下文包含注释或 nowiki 等保护区域时保守回退；模板上下文中的分类不做归属摘要。有限 compare 上下文无法证明完整页面的所有语法范围，不计算模板展开后的真实分类成员变化。
- `change_diff_lines=0` 时不请求差异及内容模型，不逐条发送“差异预览已关闭”；差异请求失败仍保留提示与差异链接。

本版按用户选择暂不加入注音模板及 `llcoloredlink` 的专用参数语义识别，也不加入页面移动日志或新建重定向专用通知。现有通用源码预览继续适用。表头不在差异上下文内时不额外抓取修订全文，而是保留行标识与源码，避免借用最新页面解释历史修改。

升级不会覆盖已保存的 900 或其他长度配置；需要 700 字符时请手动设置 `change_message_max_chars=700`。订阅状态格式仍为 v3，已有失败重试通知仍保留旧文本。注册版本、元数据与默认 User-Agent 已统一为 1.6.0。

结构回归样本及来源见 `tests/test_structured_preview.py`。包含表格单项目预算、跨行上下文、重复计数、截断碰撞、短数字行号、分类高亮错位、CSS及未知模型回退等测试。

### 1.5.1 新条目链接

新条目保留标题、`N` 标记、字节变化、编辑者、时间、订阅和编辑摘要，链接优先使用 `curid`（无有效页面 ID 时使用标题）。不显示差异关闭、失败或省略提示。此前已持久化的失败通知仍保留旧文本。

### 1.5.0 分类变更预览

对差异中能明确识别的独立分类源码，先跨行比较再生成预览。例如：

```text
✏移出分类｢Userboxes｣
✏加入分类｢Human life user templates｣
…另有空白或换行调整
```

分类汇总作为一个完整项目参与预览数量和消息长度限制，不会只显示移出而截掉加入。同类操作超过三项时展示前三项及总数。同一分类的排序键变化单独展示；未指定排序键与显式空排序键分别标注。仅调整分类源码顺序、重复项或格式时，不显示为分类增删。

正文同时变化时继续保留正文差异。仅当完整显示的单项分类预览与 HotCat 固定摘要完全对应时，才省略重复摘要；用户添加的理由仍保留。普通分类链接 `[[:Category:A]]`、注释、nowiki、模板参数中的分类语法等不做归属推断，使用原文差异兜底。当前识别支持 Category、分类、分類三个前缀；这是对可见源码变更的摘要，不代表重新计算了模板展开后的全部分类，也不包含 DEFAULTSORT 语义解析。

保留此前的新页面检查：分类监控会即时查询新页面的直接分类，不必等待完整分类树的下一次刷新；已知子分类中的新页面同样可以命中。新分类和新页面出现在同一批最近更改时，会按配置的递归深度建立关联。

考虑到分类索引可能稍晚于 RecentChanges，新页面首次未命中时默认在 900 秒内重新检查，并暂时保留时间水位；其他编辑仍通过 RCID 去重继续处理。超过窗口仍不属于监控分类的页面会正常略过。可通过 `change_new_page_grace_seconds` 调整为 0–3600 秒。

1.4.2 加入的紧凑差异仍然保留：长段落中的纯内链添加可汇总为 `✏为｢RAISE A SUILEN｣添加内链`；分散的文本修改拆成局部片段，预览每侧最多 60 字符。存在其他正文变化时不会仅汇总链接而隐藏修改。分类、文件等带名字空间的语法及包含 HTML 标签的内容不使用此简写。

可在插件配置中设置 `change_message_max_chars=700`、`change_diff_line_chars=60`、`change_diff_lines=3`，得到更紧凑的消息。整条上限包含标题、摘要、订阅、链接、差异和省略提示，范围 500–5000；差异项目完整保留或省略，不会拆开修改前后。单行字符限制分别作用于修改前后两侧，紧凑预览取配置与 60 的较小值。长度按 Python 字符数计算，不是 UTF-8 字节数。

局部文本对齐在后台线程进行，超过 2000 字符的长行使用上下文截取兜底，避免复杂对齐拖慢消息处理。带显示文字的新增内链会同时显示目标，例如 `✏为｢Apocalypse｣添加内链（目标：Apocalypse(RAISE A SUILEN)）`。

升级并重新加载后，新生成的通知使用新限制；此前已持久化的失败通知仍为旧文本。标题、摘要和订阅过长时会缩短；异常超长的自定义 API URL 也可能被总长度限制截断。

### 1.4.0 差异预览

- 在同一差异行、未变化上下文一致时，将局部修改展示为 `✏把｢anzu｣改成｢泷泽杏｣`；支持一行多处替换。
- 对应关系不明确时展示修改前后，纯新增和删除继续分别展示，不跨行强行配对。
- 保留链接、模板等 Wikitext 的附近上下文；空白变化用 `␠`、`⇥`、`↵` 等可见符号呈现。
- 预览预算以差异项目为单位，修改前后不会被拆开；优先覆盖不同差异行，超出时提示省略项目数。长片段以省略号截断。
- 标题后的 `§` 表示编辑摘要提供的章节提示，不代表已验证本次只修改该章节；分类匹配范围单独显示为 `订阅：`，单条目订阅不重复标题。
- 差异关闭、获取失败或没有可展示内容时给出提示，保留完整差异链接。

本版覆盖文本差异，不包含模板参数语义解析、段落移动识别或删除/恢复等日志监控。已有待发送通知保存的是旧版文本，升级后重试时仍按原格式发送；新抓取通知使用新版格式。

## 功能

- 返回页面规范链接或较短的 `curid` 链接
- 返回页面导言摘要
- 处理重定向、章节锚点、跨 Wiki 链接和不存在页面
- 一次查询最多 5 个页面
- 页面不存在时可搜索相近结果
- 可选自动展开普通消息中的 `[[页面名]]`
- 支持直接发送 `@机器人 [[页面名]]`，并阻止同一消息继续触发 LLM 重复回复
- 可按单一条目（pageid）或分类树订阅编辑，定时主动推送到当前群聊或私聊
- 推送编辑者、字节变化、编辑时间、差异链接与逐行增删预览
- 单条目移动或重命名后会按 pageid 继续追踪，并自动更新显示标题
- RecentChanges 使用重叠时间窗口和持久化 RCID 去重，降低延迟写入造成的漏报风险
- 相同分类的多个订阅共享分类树刷新结果，并与变更轮询分开限频
- 首次订阅跳过历史，持久化时间水位、去重记录、分类成员快照和发送失败队列
- 提供统一监控列表、运行状态和主动推送连通性测试
- 支持使用 MediaWiki Bot Password 登录受限 API，并在登录失效后自动重登一次
- 对未安装 TextExtracts 扩展的 Wiki 自动退化为仅返回页面信息
- 避免 `Special:MyPage`、`Special:MyTalk` 等特殊页暴露请求端身份

## 安装

在 AstrBot WebUI 的插件管理中通过仓库地址 `https://github.com/popipp1/astrbot_plugin_mediawiki` 安装，也可以将插件目录放入 AstrBot 的 `data/plugins/astrbot_plugin_mediawiki`。插件依赖会根据 `requirements.txt` 安装。

安装后，在插件配置中将 `api_url` 改为目标 Wiki 的 API 地址，例如：

```text
https://zh.wikipedia.org/w/api.php
https://www.mediawiki.org/w/api.php
```

地址必须以 `/api.php` 结尾。部分站点要求使用指定 User-Agent，请同时修改 `user_agent`。

### 萌娘百科等禁止匿名 API 的站点

若查询返回 `action-notallowed: Unauthorized API call`，需要在该 Wiki 登录后打开
`Special:BotPasswords` 创建一个专用于本插件的 Bot Password，然后在 AstrBot 插件配置中填写：

```text
api_url=https://zh.moegirl.org.cn/api.php
api_username=你的账号名@机器人名
api_bot_password=Special:BotPasswords 生成的密码
```

请填写 Bot Password，不要填写账号主密码。插件通过同一个 HTTP 会话先获取登录令牌，
再用 POST 登录；查询时不会把密码放入 URL 或日志。AstrBot 会将插件配置保存在本机
`data/config`，请限制该目录的访问权限。保存配置后重新加载插件，再用 `/wiki 页面名`
验证。若站点 WAF 对主域名不稳定，也可以尝试把 `api_url` 改为
`https://mzh.moegirl.org.cn/api.php`，但登录仍是更可靠的方案。

## 指令

```text
/wiki 页面名
/wiki 页面名#章节
/wiki 页面1|页面2|页面3
/wiki -d 页面名
/wiki -s 不存在的页面
/wiki搜索 关键词
@机器人 [[页面名]]
/wiki监控条目 页面名
/wiki取消监控条目 页面名
/wiki取消监控条目 全部
/wiki监控 分类名
/wiki取消监控 分类名
/wiki取消监控 全部
/wiki监控列表
/wiki监控状态
/wiki测试推送
/wiki检查更新
```

常用别名：`/维基`、`/wikisearch`、`/wikiwatchpage`、`/wikiwatchlist`、`/wikiwatchstatus`。

页面标题可以直接包含空格；下划线也会被转换为空格。`-d` 强制显示摘要，`-s` 在单个主名字空间页面不存在时继续搜索。

`@机器人 [[页面名]]` 始终有效。配置项“未 @ 机器人时也自动展开”默认关闭；开启后，普通群消息中的 `[[页面名]]` 也会触发查询。

## 条目与分类变更推送

AstrBot 管理员可以在需要接收通知的群聊或私聊中订阅一个条目：

```text
/wiki监控条目 下定决心Hand in Hand
```

插件会先解析规范标题和 pageid。即使页面后来移动或重命名，后续变更仍能依靠 pageid 匹配，并把订阅标题更新为新标题。

也可以订阅一个分类及其指定深度内的子分类成员：

```text
/wiki监控 BanG Dream!
```

插件会把它规范化为 `Category:BanG Dream!`，递归读取分类成员，并记录当前会话的 `unified_msg_origin` 作为主动推送目标。首次订阅只建立当前时间水位，不补发已有历史。相同分类被多个会话订阅时只刷新一次分类树。之后的消息格式类似：

```text
下定决心Hand in Hand
+95 | Καλλιόπη | 1:57
订阅：LoveLive!学园偶像祭 ～课后活动～（SIFAC）
https://zh.moegirl.org.cn/index.php?diff=8651943&oldid=8651800
✏添加｢==翻唱版本==｣
✏添加｢===[[You and Idol光之美少女]]=== （TBA）｣
✏添加｢{{You_and_Idol光之美少女}}｣
```

一个页面同时命中当前会话的单条目和分类订阅时只发送一次，并合并显示匹配范围。发送失败的通知不会丢弃，会写入插件数据目录并在后续轮询重试。

管理命令说明：

- `/wiki监控列表`：统一列出当前会话的单条目和分类订阅。
- `/wiki监控状态`：显示后台任务、认证、订阅数、待发送队列、变更水位和最近错误。
- `/wiki测试推送`：绕过轮询，立即向当前会话发送一条主动消息，用来排查平台是否允许主动推送。
- `/wiki取消监控条目 全部`：只删除当前会话的全部单条目订阅。
- `/wiki取消监控 全部`：删除当前会话的全部单条目和分类订阅。

取消全局最后一个订阅后，插件会清空时间水位、RCID 去重记录和待发送队列。

相关配置：

- `change_push_enabled`：后台轮询总开关，默认开启。
- `change_poll_interval_seconds`：轮询间隔，最小 30 秒，默认 120 秒。
- `change_category_depth`：子分类递归深度，默认 2。
- `change_category_refresh_interval_seconds`：分类树刷新间隔，默认 900 秒；相同分类共享一次刷新。
- `change_new_page_grace_seconds`：新页面分类识别重试窗口，默认 900 秒；设为 0 可关闭重试。
- `change_max_members`：每项监控最多保存的分类成员数，默认 5000。
- `change_overlap_seconds`：每轮从水位前方回退的秒数，默认 60 秒。
- `change_recent_rcid_limit`：持久化的已处理 RCID 数量，默认 20000。
- `change_diff_lines`：每条通知最多显示的差异项目，默认 5；设为 0 可关闭 compare 请求。
- `change_include_bot_edits`：是否包含机器人编辑。

持久化状态位于 AstrBot 的 `data/plugin_data/astrbot_plugin_mediawiki/change_monitor.json`，插件更新不会覆盖。旧版状态文件会在读取时自动迁移到 v3，无需重新订阅。分类树很大时请降低递归深度、降低成员上限或提高分类刷新间隔。

RecentChanges 可能出现时间戳略早、但稍后才可见的记录，因此 1.3 系列不再只读取严格晚于最后时间戳的更改，而是回退一小段时间并按 RCID 去重。重启后去重记录仍然有效。

## QQ 链接发送

插件默认直接返回 `https://...` 纯文本链接。若 aiocqhttp/OneBot 被 QQ 风控拦截，可在插件配置中把 `qq_link_prefix` 设置为 `#`，插件会仅对 QQ 链接添加前缀。

多结果会作为一条带空行的普通文本消息发送。可通过 AstrBot 的 `platform_settings.forward_threshold` 让较长的 QQ 回复自动折叠为合并转发。
